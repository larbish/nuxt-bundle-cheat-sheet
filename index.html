How a Nuxt bundle loads

What a build is made of, which chunks a page fetches and when, and how Static, SSR and SPA change that.

Three kinds of chunks

The entry, shared chunks, and dynamic entries: pages, layouts, components loaded with import().

Imports decide the split

A static import keeps code with its importer. A dynamic import() gives it its own chunk.

The HTML decides when

modulepreload fetches now, prefetch when idle, and anything else waits until it's needed.

The mode decides the order

Static and SSR send the same HTML. An SPA finds its chunks one after another, at runtime.

What's in a bundle

Every JavaScript file Vite writes is one of these. The client manifest tells them apart, and so do the badges in nuxt-bundle-analyzer.

Is every chunk other than the entry lazy? No. Shared chunks are static: they load with whatever imports them. Dynamic entries are the ones Vite can load later with import(), and that includes every page and layout. But "dynamic" only says how a chunk can be loaded, not when: the page and layout of the URL you open are dynamic entries, and its HTML still preloads them up front. On the playground's /chart, 6 of the 10 preloaded chunks are shared and 3 are dynamic entries.

Where your code ends up

Which chunk a file lands in depends only on how it's imported. Nuxt already splits by route: the router loads every page and layout with import().

First paint: the HTML and its stylesheets are on screen. Page interactive: Vue has hydrated the page, so its event handlers work. Nuxt ready: the root <Suspense> resolved, so app:suspense:resolve, page:finish and onNuxtReady fire and isHydrating turns false. Code deferred to onNuxtReady, such as scripts loaded with useScript, waits for the slowest preloaded chunk.

Static, SSR and SPA

Static (nuxt generate, prerendering) is SSR run once at build time: Nitro calls the same renderer and writes the HTML to disk. On one build, the /_nuxt/ tags of the SSR response and the prerendered file were identical. An SPA (ssr: false) sends the same empty shell for every URL.

Three names, three sizes

Page

The file's own chunk and CSS. pages/[[lang]]/[...slug].vue

Route

Its entries and their static imports: the Initial Load the viewer shows today. /en/:lang?/:slug(.*)*

URL

What its prerendered HTML preloads. /en/getting-started/installation

Page ⊂ route ⊂ URL, usually. A URL is bigger than its route by the dynamic components the page rendered.

Docus in numbers

  • 279.9 kB in 62 chunks loads on every page: the entry and its static imports.
  • Every docs page shares one route, which loads 302.9 kB. The route can't tell two docs pages apart: what differs is the Markdown and the components it renders.
  • Nuxt UI ships 49 prose components as dynamic entries, 40 of them under 1 kB. Each one a page renders is one more preloaded request.

Rules of thumb

01Split by route

The biggest, easiest win, and Nuxt does it for you.

02Keep the entry small

Everything app.vue, plugins and global CSS import statically loads on every page, first.

03Watch shared chunks

A shared chunk loads with every chunk that imports it. A big vendor chunk from manualChunks makes every page pay for it.

04Split what isn't on screen

Editors, charts, maps, big libraries behind a tab or a click. Then they're only prefetched.

05Splitting what renders saves nothing

With Static or SSR, a component the server renders is preloaded anyway. You add a request, it turns interactive later, and Nuxt ready waits for it.

06Don't over-split tiny components

Every chunk is a request. Many chunks under 1 kB on one page can cost more in requests than they save in bytes.

07SPA turns splits into a waterfall

Without SSR, the page chunk loads after the entry runs, and each dynamic component after the chunk that renders it.

08Measure the URL, not only the route

The rendered HTML says what a page downloads up front. Prerender the URLs you care about.

Glossary

Chunk
One JavaScript file the bundler writes.
Entry chunk
The file the HTML starts with <script type="module">.
Shared chunk
Code several chunks import statically, split out so it isn't duplicated. Loads with its importers.
Dynamic entry
A chunk Vite can load with import(): a page, a layout, a component. Often called a lazy chunk.
Route graph
A route's entry, layout and page chunks and everything they import statically.
Hydration
Vue attaching to server-rendered HTML so its event handlers work.
Nuxt ready
The root <Suspense> resolved: app:suspense:resolve, page:finish, onNuxtReady.
modulepreload
Fetch this module now, at high priority, so it's ready to run.
prefetch
Fetch this when the browser is idle, in case it's needed.
