How a Nuxt bundle loads

What a build is made of, which chunks a page fetches and when, and how Static, SSR and SPA change that.

Kinds of chunks

Vite sorts chunks into three kinds, with flags in its build manifest, which Nuxt keeps as .nuxt/dist/server/client.manifest.mjs. Nuxt splits Vite's dynamic entries by their source file.

Vite kindNuxt kindImported withLazyIn the playground's /chart

Static, dynamic, shared, lazy

Static
import x from './x'. The importer can't run until x has loaded, so x blocks it.
Dynamic
import('./x'). x loads when the code calls it, and Vite marks its chunk isDynamicEntry. Static and dynamic describe an import, not a chunk.
Shared
Imported statically by several chunks. It loads with its importers and blocks only them: with the entry it's on every page, with a page only on that page, with lazy components only when they load.
Lazy
Every path from the entry to it crosses an import(). That's every dynamic entry, plus the shared chunks only they import. Only the entry and its static imports aren't lazy. People often say "lazy" for any code splitting. Splitting makes the chunks, and lazy says when they can load: the shared chunks with Vue and Vue Router are split out but not lazy.

Lazy means a chunk can load later, not that it does: the HTML of a URL preloads the lazy chunks that URL needs.

What the HTML loads, and what it blocks

With Static or SSR, open a page's source and look at the tags under /_nuxt/. The HTML preloads every chunk the page renders up front, so the browser fetches them all in parallel, lazy components included. The tag only says when a chunk is fetched. Each rendered lazy component becomes interactive when its own chunk arrives, and a small one can arrive before the entry. Static, SSR and SPA

Static (nuxt generate) is SSR run once at build time: the /_nuxt/ tags of the SSR response and the prerendered file were identical. An SPA (ssr: false) sends the same empty shell for every URL.

Rules of thumb

01Keep the entry small

Everything app.vue, plugins and global CSS import statically loads on every page, first.

02Watch shared chunks

A big vendor chunk from a codeSplitting group is imported by everything, so every page pays for it.

03Split what isn't on screen

Editors, charts, maps, big libraries behind a tab or a click. Then they're only prefetched.

04Splitting what renders saves nothing

With Static or SSR it's preloaded anyway, as one more request.

05Don't over-split tiny components

Many chunks under 1 kB on one page can cost more in requests than they save in bytes.

06Measure the URL, not only the route

The route of /a is entry.js, a.js, utils.js. The URL also preloads Callout.js. Only the rendered HTML shows it. Compare what the HTML preloads, in bytes and chunks, not load times.
